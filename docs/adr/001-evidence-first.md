# Preserve tested experience alongside reusable administration code

AI can generate routine scripts. The durable asset here is what was checked, under
which conditions it worked, and which failure modes the next task must avoid.

Extend the existing m365management history as Microsoft Admin Toolkit. Keep legacy
paths and reference other repositories. Adopt code only when a real task needs it.
Use small JSON catalogues, standard-library search/validation tooling and hash-bound
evidence. JSON avoids a runtime package dependency for basic offline discovery.

Rejected: a bulk fork/mirror, a second parallel collection, mandatory rewriting of
all old scripts, a catalogue website, or claiming existing code is already verified.
They add ownership cost before demonstrating reuse. Historical records remain useful
but cannot validate a modified artifact. Execution records stay distinct from review
and offline test results. Private environment rules remain outside the public toolkit.
